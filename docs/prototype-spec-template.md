# Prototype 隨附規格（範本）

> **這是什麼**：web prototype 有些東西「畫不出來」——畫面怎麼進場、返回鍵去哪、鍵盤怎麼閃、對獎成功要不要震動。這些工程師一定會問，與其每次口頭補，不如 PM 交付 prototype 時**附一份填好的本表**。
> **怎麼用**：複製本檔到該功能的目錄（或貼進 spec），逐格填。填不到的格留「—」代表「用預設 / 無」，別留空（留空 = 沒想過，工程師還是要問）。
> **依據**：一致性策略見 [cross-platform-handoff.md](./cross-platform-handoff.md)；視覺規格見 [design.md](../design.md)。

## 1. Navigation Map（每個畫面一列）

> hash routing 的 prototype 看不出「這是推入還是彈出、返回鍵會回哪」。逐畫面標明。

| # | 畫面 | 從哪來 | 呈現方式 | 返回行為 | 備註 |
|---|------|--------|----------|----------|------|
| 1 | （例：掃描頁） | 首頁 FAB | **push**（全屏推入） | iOS edge-swipe 返回 / Android 系統返回鍵 → 回首頁 | 相機權限見 §5 |
| 2 | （例：對獎結果） | 掃描頁 | **modal**（蓋在上層） | 點 X 關閉，**不可**滑掉（強制看結果） | |
| 3 | （例：選擇載具） | 任意頁 | **bottom sheet** | 下滑關閉 / 點遮罩關閉 | detents 見 §2 |

**呈現方式選項**：`push`（全屏推入，有返回堆疊）｜`modal`（覆蓋、需明確關閉）｜`bottom sheet`（底部滑上）｜`tab switch`（底部 tab 切換，無堆疊）｜`replace`（取代當前、不入堆疊）

**返回行為要點**：
- iOS edge-swipe（左緣右滑）預設開啟，若某頁要**禁用**（如表單填寫中防誤觸）需註明
- Android **系統返回鍵 / predictive back** 每頁都要能答「按下去去哪」——modal/sheet 上按返回 = 關閉當層，不是離開 app

## 3. 鍵盤（有輸入欄位才填）

| 欄位 | 鍵盤類型 | Return key | 送出後行為 | 備註 |
|------|----------|-----------|-----------|------|
| （例：手機號碼） | 數字 | 「下一步」 | 跳下一欄 | |
| （例：驗證碼 PinInput） | 數字 | — | 填滿自動送出 | |
| （例：搜尋） | 預設 | 「搜尋」 | 收鍵盤、執行搜尋 | |

**通用**：
- **Keyboard avoidance**：鍵盤彈出時，作用中欄位 / 主要按鈕**不可**被遮住（畫面上推或捲動）
- 中文輸入法高度較高（含候選字列），底部固定按鈕要讓位

## 4. Haptics 觸覺回饋（金流 / 對獎關鍵時刻）

> 依 [design.md](../design.md) 精神：對獎、金流是情緒時刻，值得觸覺點綴；一般操作不用。

| 時機 | 回饋強度 | 備註 |
|------|----------|------|
| （例：對獎**中獎**） | success（成功震動） | 可搭配動效 |
| （例：對獎**未中**） | light（輕點）或無 | 別用 error 重震（未中不是錯誤） |
| （例：綁定 / 歸戶**失敗**） | error（錯誤震動） | |
| （例：Switch 切換、關鍵確認） | selection（輕微） | |

**強度對應**：iOS `UINotificationFeedbackGenerator`（success/warning/error）+ `UIImpactFeedbackGenerator`（light/medium/heavy）；Android `HapticFeedbackConstants` / `VibrationEffect`。
